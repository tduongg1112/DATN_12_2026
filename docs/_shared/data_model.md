## 2. Các bảng

Mọi `id` là `BIGINT` PK tự tăng (`GENERATED BY DEFAULT AS IDENTITY`). Mọi `created_at`/`updated_at` là `TIMESTAMPTZ NOT NULL DEFAULT now()`.

| password_hash | VARCHAR(255) | NULL | bcrypt; NULL nếu chỉ dùng Google |

### model_labels — Nhãn mô hình
| Cột | Kiểu | Ràng buộc | Mô tả |
|---|---|---|---|
| id | BIGINT | PK | |
| class_code | VARCHAR(100) | NOT NULL, UNIQUE | Nhãn đầu ra của mô hình, vd `Tomato___Late_blight` |
| label_type | VARCHAR(10) | NOT NULL, CHECK LabelType | |

### diagnoses — Lượt chẩn đoán
| Cột | Kiểu | Ràng buộc | Mô tả |
|---|---|---|---|
| id | BIGINT | PK | |
| user_id | BIGINT | FK → users, NOT NULL | |
| plant_id | BIGINT | FK → plants, NULL | SET NULL khi xoá cây |
| crop_id | BIGINT | FK → crops, **NOT NULL** | Loại cây người dùng chọn ở UC02 bước 7, **bắt buộc** (OQ-05 đổi 22/11). Migration `InitSchema` đang để NULL; feature `diagnosis` thêm migration đổi sang NOT NULL |
| original_image_url | VARCHAR(500) | NOT NULL | Ảnh gốc |

## 3. Quan hệ và hành vi khoá ngoại (ERD-doc Bảng 5.1, 6.13)

| Mã | Quan hệ | Loại | Khoá ngoại | ON DELETE |
|---|---|---|---|---|
| R1 | User (1) — (0..*) Plant | Kết hợp | `plants.user_id` NOT NULL | RESTRICT |
| R2 | User (1) — (0..*) Diagnosis | Kết hợp | `diagnoses.user_id` NOT NULL | RESTRICT |
| R3 | User (1) — (0..*) Notification | Kết hợp | `notifications.user_id` NOT NULL | RESTRICT |
| R4 | Crop (1) — (0..*) Disease | Kết tập ◇ | `diseases.crop_id` NOT NULL | RESTRICT |
| R5 | Crop (1) — (0..*) Plant | Kết hợp | `plants.crop_id` NOT NULL | RESTRICT |
| R6 | Crop (0..1) — (0..*) Diagnosis | Kết hợp | `diagnoses.crop_id` NULL | RESTRICT |
| R7 | Crop (1) — (0..*) ModelLabel | Kết hợp | `model_labels.crop_id` NOT NULL | RESTRICT |
| R8 | Disease (1) — (0..*) DiseaseImage | Hợp thành ◆ | `disease_images.disease_id` NOT NULL | CASCADE |
| R9 | Disease (0..1) — (0..*) ModelLabel | Kết hợp | `model_labels.disease_id` NULL (+ FK kép cùng loại cây) | RESTRICT |
| R10 | Plant (1) — (0..*) PlantLog | Hợp thành ◆ | `plant_logs.plant_id` NOT NULL | CASCADE |
| R11 | Plant (1) — (0..*) Reminder | Hợp thành ◆ | `reminders.plant_id` NOT NULL | CASCADE |
| R12 | Plant (0..1) — (0..*) Diagnosis | Kết tập ◇ | `diagnoses.plant_id` NULL | SET NULL |
| R13 | Reminder (0..1) — (0..*) Notification | Kết hợp | `notifications.reminder_id` NULL | SET NULL |
| R14 | Diagnosis (1) — (0..*) DiagnosisPrediction | Hợp thành ◆ | `diagnosis_predictions.diagnosis_id` (PK) | CASCADE |
| R15 | ModelLabel (1) — (0..*) DiagnosisPrediction | Kết hợp | `diagnosis_predictions.label_id` (PK) | RESTRICT |

Không có chức năng xoá tài khoản, nên mọi FK tới `users` là RESTRICT. Chuỗi RESTRICT kéo theo: nhãn đã nằm trong dự đoán thì không xoá được, do đó bệnh và loại cây đã có dữ liệu chẩn đoán chỉ được ẩn.

## 5. Quy tắc ở tầng ứng dụng (ERD-doc Bảng 6.15)

| Quy tắc | Nơi kiểm tra |
|---|---|
| Bệnh chỉ chuyển sang `PUBLISHED` khi đã có `summary`, `symptoms`, `treatment` | Service danh mục |
| `result_type`: xác suất hạng 1 < ngưỡng (một ngưỡng chung trong cấu hình, giá trị chờ nhóm AI, OQ-06) thì `UNCERTAIN`; nhãn hạng 1 là `HEALTHY` thì `HEALTHY`; còn lại `DISEASE` | Service chẩn đoán |
| Lượt `COMPLETED` có đủ k dự đoán, `rank_no` liên tục từ 1; ghi cùng một giao dịch với cập nhật trạng thái | Service chẩn đoán |
| `class_code` mô hình trả về phải có trong `model_labels` và đang dùng; nếu không thì `FAILED`, ghi log ERROR và tạo `notifications` cho mọi ADMIN, không gửi trùng cho cùng mã (OQ-26) | Service chẩn đoán |
| Gắn lượt chẩn đoán vào cây: cây phải của cùng người dùng; cảnh báo nếu loại cây khác loại cây của nhãn hạng 1 | Service chẩn đoán, cây trồng |
| `health_status` đổi theo Bảng 4.8; kết quả `UNCERTAIN` không làm đổi; xoá mềm hoặc hoàn tác lượt chẩn đoán không làm đổi (OQ-24) | Service cây trồng |
| Cập nhật `TREATING`, `RECOVERED` ghi kèm một `PlantLog STATUS_CHANGE` trong cùng giao dịch | Service cây trồng |
| Nhắc `SYSTEM` là gợi ý, chỉ tạo khi người dùng xác nhận: `RECHECK` theo `diseases.recheck_days` khi gắn kết quả `DISEASE`; `WATERING`, `FERTILIZING` theo chu kỳ của `crops` khi tạo cây. Không tạo trùng khi cây đã có nhắc cùng loại đang bật; tắt nhắc `RECHECK` khi cây `RECOVERED` (OQ-15) | Service nhắc việc |
| Người dùng chỉ đọc, sửa dữ liệu có `user_id` của chính mình | Guard xác thực (JWT) |
| Sai mật khẩu 5 lần liên tiếp thì `locked_until` = hiện tại + 15 phút; hai giá trị trong cấu hình (OQ-02) | Service tài khoản |

## 6. Dữ liệu khởi tạo (ERD-doc 7.2)

| Bảng | Dữ liệu ban đầu | Nguồn |
|---|---|---|
| users | 1 tài khoản ADMIN | Seed, đọc `ADMIN_EMAIL`, `ADMIN_PASSWORD` từ `.env` |
| crops | 5 loại cây | Theo phạm vi đề tài |
| diseases | Các bệnh có trong nhãn mô hình, trạng thái `DRAFT` | Danh sách do nhóm AI cung cấp; nội dung theo OQ-19 |
| model_labels | Mỗi loại cây 1 nhãn `HEALTHY`, mỗi bệnh 1 nhãn `DISEASE` | Import từ `GET /labels` của AI service |
| Các bảng còn lại | Không có | Sinh ra khi người dùng thao tác |

File SQL 04 có sẵn 6 bệnh và 11 nhãn làm ví dụ. Mã nhãn của lúa là giả định. PlantVillage chỉ có ớt chuông, cần hỏi nhóm AI dùng nhãn nào cho ớt.
